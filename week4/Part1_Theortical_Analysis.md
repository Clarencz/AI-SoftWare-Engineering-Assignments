Part 1: Theoretical Analysis (30%)1. Short Answer QuestionsQ1: Explain how AI-driven code generation tools (e.g., GitHub Copilot) reduce development time. What are their limitations?How they reduce time:Boilerplate Reduction: They auto-generate entire functions, classes, and repetitive code blocks (e.g., for loops, data-fetching) from a simple comment or function signature.Contextual Suggestions: They act as an "instant Stack Overflow," suggesting correct API usage, library functions, and complex algorithms (like regex patterns or sorting) without the developer needing to leave the IDE to search documentation.Limitations:Correctness: They can be "confidently wrong," generating code that looks plausible but contains subtle logic bugs, is inefficient, or fails to handle edge cases.Security: Models trained on public code may suggest outdated or insecure patterns (e.g., SQL injection, weak cryptography) if those patterns were common in the training data.Context Blindness: They excel at generic tasks but struggle to understand complex, project-specific business logic or internal abstractions. Q2: Compare supervised and unsupervised learning in the context of automated bug detection.Supervised Learning: This approach requires a labeled dataset of historical code, where each snippet is marked as "buggy" or "not buggy." A classifier is trained to recognize the patterns of known bugs (e.g., common NullPointerExceptions, resource leaks). It is effective at finding bugs similar to those seen in the past.Unsupervised Learning: This approach uses an unlabeled dataset of only valid, "normal" code. The model (e.g., an autoencoder or clustering algorithm) learns the statistical properties of correct code. It then flags new code that is a statistical anomaly or outlier, identifying novel or unusual patterns that don't conform to normal practices, which are likely to be bugs.Q3: Why is bias mitigation critical when using AI for user experience personalization?Bias mitigation is critical because AI models will learn and amplify any existing biases present in historical user data. For example, if a "personalized" IDE feature suggestion tool was trained on data primarily from senior engineers, it might suggest overly complex patterns to junior engineers, hindering their learning. This creates a discriminatory feedback loop where the tool is helpful for the dominant group but unhelpful or even harmful for underrepresented groups, leading to an unfair and inequitable user experience.
 Case Study Analysis: AI in DevOpsHow does AIOps improve software deployment efficiency? Provide two examples.AIOps (AI for IT Operations) improves deployment efficiency by moving from reactive to proactive problem-solving. It ingests and analyzes massive volumes of telemetry data (logs, metrics, traces) from the CI/CD pipeline and production environment to identify patterns humans cannot.Predictive Anomaly Detection & Risk Assessment: Before a deployment, AIOps can analyze the code changes and current system health to assign a "risk score." It can flag a new deployment as "high-risk" if it sees, for example, that a small change is being made to a highly sensitive service that is already experiencing high latency, potentially triggering an automated halt for human review.Automated Root Cause Analysis: When a deployment fails or causes a performance issue (e.g., high error rates), AIOps automatically correlates data from thousands of sources. Instead of engineers manually searching through logs, the AIOps platform can instantly identify the root cause (e.g., "Error rate spike correlates 98% with commit #f3a12d in the 'auth-service'"), reducing Mean Time to Resolution (MTTR) from hours to minutes.
